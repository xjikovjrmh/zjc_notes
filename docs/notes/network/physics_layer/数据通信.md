# 一、 数据传输

在前面的计算题中，我们涉及了一个数据从发送端到接收端经历的总时间。理解这些概念是做题的基础：

### 1. 时延的四个组成部分
数据在网络中传输，总时延由四部分组成：
*   **发送时延（Transmission Delay）**：
    *   **定义**：主机或路由器将数据帧的所有比特**推送到链路上**所需的时间。
    *   **公式**：`发送时延 = 分组大小 (bits) / 链路带宽 (bps)`
    *   *例子*：分组1000bit，带宽10Mbps（10bit/微秒），发送时延 = 100微秒。
*   **传播时延（Propagation Delay）**：
    *   **定义**：信号（电磁波/光）在物理介质中**传输一段距离**所需的时间。
    *   **公式**：`传播时延 = 链路长度 / 信号传播速度`
    *   *例子*：每段链路传播时延是10微秒。
*   **处理时延（Processing Delay）**：
    *   **定义**：路由器收到分组后，进行**排队、查表、拆装**等操作的时间。
    *   *例子*：题目给出“每个路由器中存储排队与拆装等时延是100微秒”。
*   **排队时延（Queuing Delay）**：
    *   **定义**：分组在路由器缓存队列中等待处理的时间（网络拥塞时这个时间会很大）。

### 2. 分组交换中的“流水线”效应（易错点）
在计算“从H1发完到H2接收完所有分组的总时间”时，**不能简单地把所有分组的所有时延相加**。
*   因为当第2个分组在第1台路由器处理时，第1个分组可能已经在第2台路由器处理了（它们是并行的）。
*   **正确计算口诀**：`总时间 = 前面(N-1)个分组的发送时间 + 最后一个分组的全链路时间`
    *   *注：N为总分组数，最后一个分组的全链路时间包括它自己的发送时延、所有路由器的处理时延、所有链路的传播时延。*

# 二、 差错控制概述

数据在传输过程中，由于噪声、干扰等原因，难免会发生“比特差错”（0变1，1变0）。差错控制的核心就是**如何发现并处理这些错误**。
主要分为两大类：
1.  **检错（Detection）**：只发现错误，然后丢弃，要求重传（依靠 ARQ 机制）。
2.  **纠错（Correction）**：不仅发现错误，还能定位并纠正错误（前向纠错 FEC）。

---

# 三、 奇偶校验（Parity Check）—— 最简单的检错法

### 1. 原理
在原始数据后附加 **1位** 校验位，使得整个数据（含校验位）中“1”的个数满足约定。
*   **奇校验**：让“1”的总数为奇数。
*   **偶校验**：让“1”的总数为偶数。

### 2. 计算示例
*   原始数据：`1100001` （里面有3个1）
*   若采用**偶校验**，需要补1个 `1`，变成 `11000011`（总共4个1）。
*   若采用**奇校验**，需要补1个 `0`，变成 `11000010`（总共3个1）。

### 3. 优缺点
*   **优点**：极其简单，开销极小（只加1位）。
*   **缺点**：**检错能力极差**。如果同时有偶数个比特发生翻转（比如2个1变成了2个0），1的个数奇偶性没变，接收方就会**误认为数据正确**。因此，计算机网络中很少单独使用它。

# 四、 循环冗余校验（CRC）—— 网络中最主流的检错法

### 1. 核心概念
*   **模2运算（异或）**：没有进位和借位的二进制加减法。`0 XOR 0 = 0`，`1 XOR 0 = 1`，`1 XOR 1 = 0`。
*   **生成多项式 G(x)**：收发双方事先约定的一个二进制比特串（例如 `10101`）。
*   **FCS（帧检验序列）**：计算出来的冗余码（余数），附加在数据后面一起发送。
*   **最高次幂 r**：生成多项式的最高次幂（例如 `x^4 + x^2 + 1` 的 r=4），决定了 FCS 的位数是 4 位。

### 2. 发送方：如何计算 FCS？
1.  **补零**：在原始数据 M 后面补上 r 个 0。
2.  **模2除法**：用补零后的数据，除以生成多项式 G(x)（做异或运算，不借位）。
3.  **取余数**：除完后剩下的 r 位余数，就是 FCS。
4.  **拼接**：将原始数据 M 与 FCS 拼接，作为最终发送的数据 T。

*   *示例*：原始数据 `110101`，生成多项式 `10101`（r=4）。
    补零后 `1101010000` 除以 `10101`，余数为 `0010`。
    最终发送：`1101010010`。

### 3. 接收方：如何校验？
1.  接收方收到数据 T。
2.  用同样的生成多项式 G(x) 去除以 T（模2除法）。
3.  **如果余数为 0**：说明传输无误，接收。
4.  **如果余数不为 0**：说明出错，直接丢弃，通知发送方重传。

### 4. CRC 的优缺点
*   **优点**：
    *   **检错能力极强**（能检测出所有奇数个错误、所有双比特错误、所有突发长度小于等于 r 的错误）。
    *   **硬件实现极其简单**：只需要移位寄存器和异或门，速度极快（现代网卡轻松跑满带宽）。
    *   **开销可控**：FCS 长度（如以太网用 CRC-32，即 32 位）可灵活选择。
*   **缺点**：
    *   **只能检错，不能纠错**。发现错误后只能丢弃重传。
    *   在延迟极大的网络中（如卫星通信），重传效率低，此时需要配合纠错码（如海明码）使用。

# 💡 总结记忆法（针对考试）

1.  **时延计算**：分清**发送时延**（数据推上链路）和**传播时延**（信号跑在路上）。总时间算流水线时，别忘加最后一个分组的全链路时间。
2.  **奇偶校验**：数“1”的个数。偶数个错检不出。
3.  **CRC**：记清“**补零、模2除、取余数、拼后面**”八字口诀。
4.  **模2除法**：**无借位异或**。相同为0，不同为1。这是为什么硬件喜欢它的根本原因。
