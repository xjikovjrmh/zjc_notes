# TCP 三次握手

> 示例笔记，演示代码块和提示框排版。

## 为什么需要三次

核心目的：**双方都确认"我的发送能力"和"你的接收能力"都正常，并同步初始序列号（ISN）。**

```text
客户端                                服务端
  │                                     │
  │ ──────── SYN, seq=x ──────────────► │   ① 客户端：我要连你
  │                                     │
  │ ◄──── SYN+ACK, seq=y, ack=x+1 ───── │   ② 服务端：收到，我也要连你
  │                                     │
  │ ──────── ACK, ack=y+1 ────────────► │   ③ 客户端：收到，连接建立
  │                                     │
```

## 三次握手的报文要点

| 步骤 | 标志位 | 关键字段 | 含义 |
| --- | --- | --- | --- |
| ① | SYN=1 | seq=x | 客户端请求建立连接，告知自己的初始序号 |
| ② | SYN=1, ACK=1 | seq=y, ack=x+1 | 服务端同意，并告知自己的初始序号 |
| ③ | ACK=1 | ack=y+1 | 客户端确认，连接正式建立 |

::: tip 为什么不是两次
如果只握手两次，服务端无法确认**客户端的接收能力**是否正常；而且网络上滞留的旧 SYN 报文可能让服务端白白建立一条无用连接。
:::

::: details 为什么不是四次
第 ② 步把 SYN 和 ACK 合并成了一个报文，因为服务端在收到 SYN 后可以立即回 ACK 并同时发起自己的 SYN，没有必须分开的理由。
:::

## 相关：四次挥手

断开连接需要四次，因为 TCP 是全双工的，两个方向要各自关闭：

| 步骤 | 报文 | 说明 |
| --- | --- | --- |
| ① | FIN | 客户端说"我没数据要发了" |
| ② | ACK | 服务端说"知道了"（此时可能还有数据要发） |
| ③ | FIN | 服务端说"我也发完了" |
| ④ | ACK | 客户端说"知道了"，等待 2MSL 后关闭 |

## 常见面试追问

1. **SYN 洪泛攻击是什么？** 攻击者大量发送 SYN 但不完成第三次握手，耗尽服务端的半连接队列。防御手段之一是 SYN Cookie。
2. **2MSL 是多久？** MSL 是报文最大生存时间，2MSL 保证最后一个 ACK 能到达，并让本次连接的旧报文全部消亡。
