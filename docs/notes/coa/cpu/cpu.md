# 模块一：早期指令系统（IAS机）与微操作

## 1. 核心概念：微操作与控制信号
*   **微操作**：CPU在一个时钟周期内完成的最基本、不可再分的操作（如：打开某寄存器的输出门，把数据打入另一个寄存器）。
*   **控制信号**：由操作控制器（OC）发出的指令，用于控制硬件门电路的开关。
    *   **输出控制信号（`Xout` / `XoutE`）**：打开寄存器的三态门，将数据放到总线上。
    *   **输入控制信号（`Xin` / `XinE`）**：打开寄存器的输入门，从总线抓取数据并保存。
    *   **存储器读写信号（`MemR` / `MemW`）**：直接发给内存的命令，控制读或写。
    *   **运算控制信号（`Add` 等）**：命令ALU执行特定的算术或逻辑运算。
*   **三态门（Tri-state Gate）**：连接寄存器与总线的“智能大门”。具有高电平（输出）、低电平（输入）、**高阻态（物理隔离，不干扰总线）**三种状态。确保同一时刻总线上只有一个数据源。
*   **带E与不带E的区别**：
    *   不带E（如 `MDRout`）：用于 **CPU内部总线** 的数据传输（如取指令到IR）。
    *   带E（如 `MDRoutE`）：用于 **CPU外部总线（系统总线）** 的数据传输，特指与内存交互（配合 `MemR`/`MemW`）。

## 2. 经典指令的执行过程（LAD、STO、ADD）
*   **数据通路**：数据在寄存器、ALU和内存之间传输的路径。在单总线结构中，数据必须分时、分步地通过总线，这就是为什么看似简单的操作会“绕一圈”。
*   **LAD R1, 6（读内存）**：
    *   指令地址送入AR -> 读内存 -> 数据送入DR -> 最终送入目标寄存器R1。
*   **STO R2, (R3)（写内存）**：
    *   寄存器R3的值（地址）直接放到DBUS上 -> 送入AR -> 寄存器R2的值（数据）放到DBUS上 -> 配合MemW写入内存。
*   **ADD R0, (R1)（算术运算）**：
    *   分步取操作数（C5-C7周期）-> 进入ALU运算，一步完成加法和写回（C8周期：`AC ← (R0) + (A)`）-> 最终把结果写回内存或寄存器（C9-C10周期）。

# 模块二：指令流水线与处理器体系结构（SEQ模型）

## 1. 经典的五级流水线阶段（SEQ Stages）
现代处理器为了提高效率，不再是一条指令执行完再执行下一条，而是将指令执行划分为五个标准的阶段，像流水线一样并行处理：
1.  **Fetch（取指）**：根据PC地址从指令内存中读取指令，并让PC自增（+1）。
2.  **Decode（译码）**：拆分指令，从寄存器堆中读出源操作数。
3.  **Execute（执行）**：ALU进行算术或逻辑运算。
4.  **Memory（访存）**：如果需要，从数据内存中读取数据或写入数据。
5.  **Write back（写回）**：把ALU计算的结果或从内存读出的结果，写回寄存器堆。

## 2. 数据通路与中间变量（Computed Values）
在流水线的各个阶段之间，会传递特定的中间数据（变量）：
*   **Fetch阶段**：`icode`(指令代码)、`ifun`(功能码)、`rA`/`rB`(源寄存器号)、`valC`(常数)、`valP`(自增后的PC)。
*   **Decode阶段**：`srcA`/`srcB`(源寄存器地址)、`dstE`/`dstM`(目的寄存器地址)、`valA`/`valB`(从寄存器读出的真实数据)。
*   **Execute阶段**：`valE`(ALU计算结果)。
*   **Memory阶段**：`valM`(从内存读出的数据)。

## 3. 指令编码格式（Instruction Format）
*   指令在内存中是以二进制位（bit）的形式存储的。
*   一条指令通常被切分为多个字段：`icode` (指令类型)、`ifun` (具体功能)、`rA`/`rB` (寄存器编号) 以及 `D` (常数或地址偏移量，通常为**Optional可选**，只有部分指令需要)。
*   指令编码决定了流水线中译码阶段（Decode）如何知道该从哪个寄存器取数，以及执行阶段（Execute）做什么操作。

**总结**：从早期IAS机的“微操作”中，我们看到了CPU内部最底层的硬件信号如何控制门电路开关；而在SEQ模型中，我们看到了这些底层操作如何被组织成标准化的“五级流水线”，从而支撑起现代计算机的高效运转。
